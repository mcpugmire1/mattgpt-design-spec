## What drifted and why it matters

Documentation drifts from code in every real system. This audit found it here too. The same number lived in five different docs. A headline metric was stale. Brand vocabulary the product had retired months earlier was still sitting in test expectations. The rules file itself was wrong on two configuration values where this spec was right.

None of this was catastrophic. All of it would have been noticed by a technical reader in the first five minutes.

## The mechanism going forward

The root cause of drift is duplication: the same fact declared in multiple places. When it changes in one, the others lag. The correction is to stop declaring and start deriving.

A GitHub Actions pipeline keeps `_data/facts.yml` in sync with the running code: on every push to the source repo, a job derives volatile facts (model name, thresholds, intent family count, test counts, story count) and writes them here. Jekyll Liquid references replace hardcoded numbers. A fact changes in exactly one place, the code, and the docs stay current without a review queue.

The audit was the manual version of that mechanism. The pipeline is the automated one.
